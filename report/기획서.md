## 1. 프로젝트 개요

### 배경 및 필요성
도구를 호출하는 LLM 에이전트가 확산되며, 공격은 더 이상 사용자 발화가 아니라 **에이전트가 읽는 도구 반환값(검색 문서·티켓·메모)** 을 통해 들어온다(간접 프롬프트 인젝션, EchoLeak CVE-2025-32711과 동형). KISA·과기정통부 「AI 보안 레드티밍 가이드」(2026-07-07)도 프롬프트 인젝션·에이전트 하이재킹을 위협으로 지목하나 **한국어 테스트 코퍼스는 제공하지 않는다.** 또한 한국어 안전 분류기(Kakao Kanana)는 단일 발화만 채점해 도구 채널을 구조적으로 볼 수 없고, 널리 쓰이는 영어 분류기(Prompt Guard)는 평가 언어에 한국어가 없다. **한국어 에이전트의 도구 채널을 실증적으로 평가·방어할 공개 수단이 부재하다.**

### 프로젝트 목표
1. 도구 사용 한국어 에이전트를 4개 seam(before/after_model·tool)으로 감싸는 **안전 런타임** 구현.
2. **KoTIP-Bench** — 한국어 도구채널 인젝션·PII 유출 평가 코퍼스 구축(공개 목표).
3. **핵심 논지 실증** — 결정적 정책 게이트는 언어·난독화 무관하게 인젝션을 막지만, 분류기 기반 방어는 둘 다에 취약함을 **층별 애블레이션 표(McNemar 검정)** 로 증명.
4. 홉 간 일관 **가역 PII 볼트**로 개인정보 유출을 싱크별 0%로 억제.

### 적용 분야
한국어 고객지원·업무비서 등 도구 사용 LLM 에이전트의 안전 런타임. 도메인 재스킨 가능.

### 합성이 요건인 이유
실제 한국어 PII 는 사용 불가(PIPA + 무료 티어 학습 가능성). 따라서 CRM·PII 골드셋은 **합성**하며(주민번호는 형식만·체크섬 불만족), 이는 약점이 아니라 요건이다. **공개 한국어 코퍼스에 유효한 주민등록번호가 0건**이라는 것은 측정된 공백이다.

### 수집·전처리·분할
- KoTIP-Bench: money smoke 에서 라이브 발동 확인된 confused-deputy 패턴 골격 × 5 스타일 × 6 난독화(프로그램적, `eval/obfuscate.py`) × 시나리오. 카나리는 egress allowlist 밖(빌더 assert).
- Nemotron: 에피소드 → (text,label) projector(1272→1271), **domain-grouped 60/20/20**(랜덤 분할 금지 — 템플릿 누수 차단), 음성은 동일 필드에서 채굴(도메인 분류기화 방지).
- 난독화는 오염 페이로드에만 적용. 학습/홀드아웃 계열 분리(한국어 고유: 자모분해·초성체).

Google 모델은 **온디바이스 안전분류기(ShieldGemma)**로 EN-KO 갭(0.268) 실측에 기여하고, Tier C 격리 Q-LLM 후보다.

### Ko-AgentGuard 레일 학습 (실행 완료)
- **구조:** char_wb(3-5) + word(1-2) TF-IDF + LogisticRegression(class_weight=balanced). 한국어 형태소 분석 불필요, CPU 수 분.
- **입력:** 도구 출력 텍스트 → 인젝션 확률 [0,1]. **학습:** Nemotron train 1663, in-domain F1 0.99.
- **RunPod 확장:** e5-small 임베딩 / Kanana 로짓 스윕 — 동일 `RailScorer` 계약으로 스왑.
- **⚠️ 기여는 파인튜닝이 아니라 측정** — 강한 탐지기(F1 0.99)도 난독화(base64)에 F1 0 붕괴, 영어학습은 한국어에 눈멂(0.022). QLoRA 는 배관 리스크로 미채택.

## 5. 성능 평가 및 검증 계획 (실측)

### 기존 시스템 대비 비교 (5-arm 애블레이션 표, n=60)
| arm | t-ASR | McNemar p | 판정 |
|---|---|---|---|
| 무방어 | 0.17 | — | 기준선 |
| +plea (프롬프트 애원) | 0.18 | n.s. | theater |
| +spotlight (데이터마킹) | 0.25 | n.s.(오히려↑) | theater |
| +classifier_gate (온디바이스 분류기 강제) | 0.17 | n.s. | theater |
| **+Tier A 결정적 게이트** | **0.00** | **0.002**(탐색적) | **genuine** |

> ⚠️ **p값 정직 표기(결과보고서·RESULTS 와 동일):** 행 단위 p=0.002는 **탐색적**이다 — 60건이 2시나리오×5스타일×6난독화라 난독화 변형이 상관돼 독립을 과대가정한다. 시나리오×스타일 10군집 보수적 재분석은 **p=0.125(n.s.)**. **post-hoc 민감도 분석 v0.2**(과업 시나리오 2→12, 난독화 제거)에서 시나리오 단위(n=12) 무방어 6/12 → Tier A 0/12, discordant 6:0, **exact p=0.03125**. theater 3종은 v0.2 에서도 전부 p=1.0. ⚠️ post-hoc + none 대비 4-arm 다중비교(Bonferroni α/4=0.0125) 보정 시 미유의라, 헤드라인 주장은 **"구조적으로 모든 성공 시나리오 차단(방향 일관) + 보정 전 p=0.031"**로 한정한다.

**해석:** 프롬프트·데이터마킹·분류기 강제 3종은 전부 유의성 없음. 결정적 게이트만 견고한 바닥. classifier 는 스키마상 log-only 로 고정, 강제는 `defenses.classifier_gate` 축(fail-open, Tier A override 불가)에서만 — 봉인 테스트로 보장. (전체 7-arm: 누적 arm `tier_a_b`·`cg_plus_tier_a` 도 t-ASR 0.00 = A 단독, p=1.0 → Tier B/분류기 한계이득 0.)
> ⚠️ **정직한 귀속:** classifier_gate arm 은 **영어학습 CPU 레일**로 측정했고 한국어 인젝션을 0.022 로 채점해 **한 번도 발동 못 한다**(교차언어 눈멂). "분류기 무효"가 아니라 "교차언어 theater"로 귀속하며, 한국어 가능 분류기(Kanana) 강제(P6a)는 미측정이다. GPU 실측 §4b 의 Kanana P1a(발화 1.0→도구채널 0.0)가 채널 맹점의 직접 증거다.

| **Prompt Guard 2**(Meta) | 입력 분류기 | ✗ | 단일 발화 | 평가언어 미포함 | 동상 |
| **NeMo Guardrails**(NVIDIA) | Colang 룰 + **LLM 자기점검**/임베딩 | ✗(LLM 판단 의존) | 대화 흐름 | 특화 없음 | LLM 점검도 난독화·라운드트립에 취약(cf. R11) |
| **AgentDojo**(ETH) | 벤치마크+방어 스위트(툴필터 등) | 방어별 | 에이전트 과업 | 영어 과업 | 런타임 아님(평가 프레임). 위협모델 유사, 언어·강제지점 상이 |
| Kanana-safeguard(Kakao) | 한국어 **분류기** | ✗ | **단일 발화**(도구채널 맹점) | 한국어 ✓ | 채널 격차 실측(P1a 1.0→0.0) — 분류기의 구조적 한계 |
| **SafeAgent-KR(본)** | **결정적 per-tool 게이트** | **✓**(도구 정체성·인자만, 문자열 무관) | **도구 인자 직접** | **한국어 네이티브** | 강제=게이트 / 분류기=텔레메트리 |

> **핵심 차별점:** 위 전부 강제를 **학습 분류기/LLM 판단**에 둔다 → 난독화·교차언어·라운드트립에 원리적으로 취약. 본 프로젝트는 강제를 **문자열을 읽지 않는 결정적 게이트**로 이관해 이 축들에 **불변**이고, 분류기는 *어디서 무너지는지 측정하는* 로그전용 텔레메트리로 강등한다. 이 재배치 자체가 기여다.
