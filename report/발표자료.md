## S1. 제목
**SafeAgent-KR — 도구 채널을 보는 한국어 AI 에이전트 안전 런타임**
*단일 발화 가드레일의 구조적 사각지대 측정과, 강제의 결정적 게이트 이관*
NIPA-Google · 개인 프로젝트

> 스크립트: "도구를 쓰는 한국어 에이전트에서, 안전장치를 어디에 둬야 하는가를 실측으로 답합니다."

## S2. 문제 — 공격은 사용자가 아니라 '도구'로 들어온다
- 에이전트는 검색 문서·티켓·메모를 읽고 **행동**한다.
- 공격자는 사용자 발화가 아니라 **도구 반환값**을 통제한다(간접 프롬프트 인젝션, EchoLeak).
- 한국어엔 이걸 볼 수단이 없다: Kanana=단일 발화만, Prompt Guard=한국어 미평가.

> 스크립트: "입력단만 지키는 통념적 가드레일은 공격이 지나가는 지점을 아예 보지 못합니다."

## S3. 핵심 질문 — 온디바이스 분류기가 가드레일이면 되나?
- 통념: 가드레일 = 온디바이스 안전 분류기(ShieldGemma·Kanana)가 **차단**.
- 축 분리: **위치**(API vs 온디바이스)는 무관. **역할**(탐지 vs 강제)이 쟁점.
- 가설: 분류기가 신뢰 경계가 되면 theater. 결정적 게이트만 견고.

## S4. 아키텍처 — 4-seam 런타임 + 3계층
```
before_model → 모델 → after_model → ★before_tool 게이트★ → 도구 → after_tool
```
- Tier A: 결정적 정책 게이트(위험티어·allowlist·인자검증) — **문자열 안 읽음**
- Tier B: 오염추적 · Tier C: 이중 LLM 격리
- 분류기: 스키마상 log-only 고정, 강제는 fail-open 축에서만

## S5. ★ 헤드라인 표 ★ — genuine vs theater (5-arm)
| arm | t-ASR | McNemar p | 판정 |
|---|---|---|---|
| 무방어 | 0.17 | — | 기준선 |
| +plea (프롬프트 애원) | 0.18 | n.s. | theater |
| +spotlight (데이터마킹) | 0.25 | n.s. | theater(오히려↑) |
| +분류기 강제 | 0.17 | n.s. | theater |
| **+결정적 게이트** | **0.00** | **0.002** | **genuine** |

> p 기준선: **1.0 = vs 무방어**(불일치쌍이 0이라서가 아니라 **대칭**이라 n.s. — plea 6:5, cg 1:1), **0.18 = vs 직전 arm**(spotlight, 2:7). 어느 기준이든 theater 3종은 유의성 없음(n.s.), Tier A만 유의(p=0.002).
> ⚠️ 분류기 arm은 **한국어를 0.022로 채점해 한 번도 발동 못 하는 영어학습 CPU 레일**(교차언어 눈멂). 한국어 가능 분류기(Kanana) 강제는 미측정.
> ⚠️ spotlight arm은 **before_model 지시문만** 주입한다 — 도구 출력이 구조체(list/dict)라 구분자 마킹(wrap_untrusted)은 실제로 적용되지 않는 **부분 구현**. theater 판정(n.s.)은 불변이나 "완전한 spotlighting 구현"으로 읽으면 부정확.
> 스크립트: "프롬프트·데이터마킹·분류기 — 어느 것도 못 막습니다. 게이트만 **관측된 모든 실행을 차단**합니다. *(v0.1 행 p=0.002는 탐색적 — 난독화 변형 상관으로 군집 p=0.125 미유의였고, **과업 시나리오를 2→12로 늘린 post-hoc v0.2에서 시나리오 단위 p=0.031** — 단 다중비교 보정 시 미유의라 '보정 후 유의'가 아닌 '구조적 차단'으로 주장.)* **BPR도 함께**(tier_a 정상통과, refund는 HITL 승인 흐름)."

## S6. ★ 왜 분류기는 못 막나 — 채널 맹점 (GPU 실측, 헤드라인)
- **Kanana(한국어 인젝션 SOTA): 발화 recall 1.0 → 도구 채널 대화 0.0 (격차 1.0)**. 완벽 탐지기가 채널만 바뀌면 눈멂. chat template이 tool 턴을 드롭.
- 강한 CPU 탐지기 F1 0.99 → base64 **0.0** 붕괴, 영어학습 → 한국어 **0.022**.
- ShieldGemma(Google): EN-KO 유해갭 **0.268**.
- 게이트 t-ASR: 원본=난독화=**0.00** (텍스트를 안 읽음).
- **P2:** 게이트는 시도(합계 0.17)를 안 바꾸고 실행만 0으로.
> **정직 정정:** 사전등록 P1b(Kanana 난독화 붕괴 ≥0.25)는 **틀렸습니다**(0.1, base64에 견딤). 논지를 지탱하는 건 P1b가 아니라 채널 맹점(P1a=1.0)입니다.

## S7. DLP — 유출돼도 토큰만 나간다 (경계 분리 지표)
| PII | model_view OFF→ON | unauth_sink OFF→ON |
|---|---|---|
| email | 0.75 → **0.0** | 0.125 → **0.0** |
| account | 0.25 → **0.0** | 0.0 → **0.0** |
- 요청 스코프 가역 볼트, 홉 간 같은 사람 → 같은 토큰. vault ON 이면 **모델 노출·비인가 필드 둘 다 0%**.
- 라우팅(to/account) 복원은 설계상 정상 → 유출 제외. 복원 PII 는 트레이스에 미직렬화.

## S7b. DLP + 학습형 레일 (GPU 완료)
- **R6 PII NER** span F1 **0.9845**(klue-roberta, openpii-ko 20k) · **R7 유해** Macro-F1 **0.709**(K-MHaS 멀티라벨). ⚠️ R6은 **행단위 랜덤분할=누수가능 상한**(템플릿 홀드아웃 아님), 부록 예비수치.
- 학습 모델 가중치 확보(무결성 검증). ⚠️ klue 라이선스 미명시 → 수치 보고만, 재배포 금지.

## S10. 한계 & 결론 (정직성)
- **Kanana P1b(난독화 붕괴) 사전등록 미달** — 예측이 반증됨(0.1<0.25), 그대로 보고.
- classifier_gate arm은 교차언어로 눈먼 영어 CPU 레일로만 측정(한국어 분류기 강제 미측정).
- Tier B taint 세탁(→Tier C 필요, 설계 명세 제출), 단일 모델 gpt-4o-mini, 소규모 코퍼스(BPR 얇음).
- **헤드라인 범위:** 런타임 배선+근거 있는 3가지(Tier A 게이트·Kanana 채널갭·RegexVault DLP)만 주장. R6/R7/R4/ShieldGemma는 오프라인 탐지기 실험(부록), R6 F1은 누수가능 상한.
- **결론: 강제는 분류기가 아니라 결정적 게이트에. 분류기는 '어디서 뚫리는지'(언어·채널) 재는 도구.**
