## 요약 (Executive Summary)

도구를 호출하는 한국어 AI 에이전트의 안전 런타임 **SafeAgent-KR** 을 구현하고, 한국어 도구채널 인젝션 평가셋 **KoTIP-Bench** 위에서 방어층별 애블레이션을 실측했다. 핵심 발견은 하나의 표로 압축된다:

> **결정적 정책 게이트(Tier A)는 관측된 모든 인젝션 실행을 차단한다(17% → 0%). 온디바이스 분류기(영어 CPU 레일)를 강제 경계로 쓰는 관행적 구성은 한국어 도구채널에서 무효(p=1.0)다.**
>
> ⚠️ **p값 정직 표기:** v0.1 행 단위 McNemar **p=0.002는 탐색적**이다 — 60건이 2시나리오×5스타일×6난독화라 난독화 변형이 상관되어 독립을 과대가정한다. 시나리오×스타일 **10군집** 보수적 재분석은 무방어 4/10 → Tier A 0/10, **exact p=0.125**(α=0.05 미유의). **post-hoc 민감도 분석 v0.2**(과업 시나리오 2→12, 난독화 제거, `eval/expansion_v2.py`): 보수적 시나리오 단위(n=12) 무방어 6/12 → Tier A 0/12, discordant 6:0, **exact p=0.03125**. theater 3종은 v0.2 에서도 전부 p=1.0. ⚠️ 단 (i) post-hoc 이고 (ii) none 대비 4-arm 다중비교라 Bonferroni α/4=0.0125 보정 시 미유의이며 (iii) 12 시나리오가 동일 5템플릿·싱크를 재사용하므로, 주장은 **"구조적으로 모든 성공 시나리오 차단(방향 일관) + 보정 전 시나리오 단위 p=0.031"**로 한정한다("보정 후 유의" 아님). *(교차-provider(Gemini)는 free-tier 쿼터로 미완, `results/gemini_confirmatory_note.md`.)*

이는 "분류기는 (온디바이스든 아니든) 텍스트를 읽으므로 언어·난독화에 취약하고, 게이트는 구조로 판정하므로 불변"이라는 논지를 실측으로 증명한다. 부수적으로 가역 PII 볼트가 원본 개인정보의 외부 싱크 유출을 전 항목 0%로 억제했고, Presidio 한국어 인식기의 재현 가능한 결함 2건을 정량 보고했다.

## 1. 핵심 결과 — genuine vs theater

### 1.1 인젝션 방어 애블레이션 (t-ASR, n=60)

| arm | t-ASR | McNemar p(vs 직전) | 판정 |
|---|---|---|---|
| 무방어 | 0.17 | — | 기준선 |
| classifier_gate (온디바이스 분류기 강제) | 0.17 | 1.0 | **theater** — 아무 효과 없음 |
| **Tier A 결정적 게이트** | **0.00** | **0.002** | **genuine** — 유의하게 차단 |

**세 가지 사전등록 예측이 데이터로 확인됐다:**
- **P2 (게이트는 시도가 아니라 실행을 막는다):** Tier A 하에서도 모델의 공격 시도율(ASR_attempted)은 0.17로 유지되나 실행률(executed)만 0으로 떨어진다. 게이트는 모델의 의도를 바꾸지 않고 행동만 차단한다.
- **P4 (난독화 불변):** Tier A 의 t-ASR 은 원본(0.00)과 난독화(0.00)가 동일하다. 게이트는 문자열을 읽지 않고 구조화된 인자와 정책 테이블만 보므로, 페이로드가 base64든 자모분해든 판정이 같다.
- **분류기 무효(교차언어):** 영어로 학습한 온디바이스 분류기는 한국어 인젝션 문서를 점수 0.022로 채점(임계 0.5 미달) — 무방어와 통계적으로 구분되지 않는다(p=1.0).
- **누적 arm(7-arm 전체, 강등 논지 직접 확증):** Tier A 위에 방어를 더 얹어 봐도 t-ASR 은 **0.00 그대로**다. `tier_a_b`(A+오염추적) p=1.0 vs A — Tier B 는 한계이득 0 이면서 정상 유틸만 비용화 → **로그전용 강등 근거**. `cg_plus_tier_a`(분류기+A) p=1.0 vs A+B — 분류기를 게이트 위에 얹어도 결과 불변 → **"강제는 게이트, 분류기는 텔레메트리"의 직접 증거**. (전체 표: `results/ablation_table.md`.)

### 1.2 왜 이 비교가 공정한가 (designed-to-win 반박 방어)
- 분류기 강제는 `classifiers.*`(스키마상 log-only 고정)가 아니라 별도 `defenses.classifier_gate` 축(fail-open)에서만 표현되며, 분류기의 benign 판정은 Tier A 의 Block 을 **절대 무효화할 수 없다**(봉인 테스트 `test_rail_cannot_override_gate.py`).
- 헤드룸이 실재함을 먼저 확인(무방어 17% ≥ 10%)했고, 이 값과 사전등록을 **결과 산출 이전**에 커밋했다.

## 2. 탐지기 붕괴 — 강한 분류기도 뚫린다 (P3)

우리가 만들 수 있는 최선의 CPU 탐지기(Ko-AgentGuard, in-domain F1 **0.9936**)조차:
- **base64 난독화 → F1 0.000** (완전 붕괴, 붕괴폭 0.99 ≥ 목표 0.25)
- 영어학습 → 한국어 인젝션 **0.022** (교차언어 눈멂)
- 반면 zero-width·자모분해는 char n-gram 이 견딤(0.99) — **"모든 난독화가 뚫는 게 아니라 특징 표현에 의존한다"는 정직한 미묘함**.

→ 분류기는 언어(한국어)와 난독화(base64) **양쪽**에 취약. Tier A 는 양쪽 모두에 불변. 이것이 "강제는 분류기가 아니라 게이트에 있어야 한다"의 실증.

## 3. DLP — 홉 간 일관 가역 PII 볼트 (H7)

외부 싱크로 나가는 원본 PII 를 **두 계측 경계로 분리**(재구현 `eval/dlp_eval.py`, n=8):
**model_view**(모델 인자에 원본 PII) · **unauthorized_sink**(실행 인자의 비-라우팅 필드 body/reason 에 원본 PII;
라우팅 to/account 복원은 설계상 정상이라 제외).

| PII | model_view OFF | model_view **ON** | unauth_sink OFF | unauth_sink **ON** |
|---|---|---|---|---|
| email | 0.75 | **0.0** | 0.125 | **0.0** |
| account | 0.25 | **0.0** | 0.0 | **0.0** |
| phone | 0.125 | **0.0** | 0.125 | **0.0** |

vault **ON 이면 두 경계 모두 0%**. 요청 스코프 1개 볼트가 루프를 관통하며 같은 사람 → 같은 토큰(홉 간 coreference 유지), 최종 복원 정확. 인젝션이 유출을 시도해도 **모델은 토큰만 본다.** (복원된 실제 PII 는 in-memory 계측 전용 — traces.jsonl 로 직렬화 안 함.)

> ⚠️ **계측 경계 정직 표기:** 이 0%가 정확히 증명하는 것은 **"모델이 생성한 도구 인자(tool_args)에 원본 PII 가 없다"(모델 출력 기준)**이다. 모델이 **입력에서** 원본을 보지 못하는 것은 이 지표가 아니라 볼트의 before_model 토큰화가 설계로 보장하는 별개 속성이다. 서비스의 egress 사전복원은 send_email 수신자/계좌를 **라우팅을 위해 실제 값으로 복원해 백엔드에 넘기므로**, *"외부 도구가 원본 PII 를 전혀 받지 않는다"* 는 주장은 성립하지 않는다(수신자 주소는 본질적으로 데이터주체 식별자). 유효 주장 = (a)모델 출력 원본 0 · (c)subject/body/reason 비인가 PII 차단 · (d)비인가 목적지 차단.

## 5. 한계 (정직한 서술)

- **Tier B taint** 는 LLM 라운드트립으로 세탁된다. value-provenance 휴리스틱으로 실동작을 부여했으나 egress allowlist 가 선점해 독립 기여는 미미(분기 B). **이것은 분류기를 무력화하는 바로 그 메커니즘이 taint 도 무력화함을 보이며, 완전한 해법이 Tier C(격리) 임을 시사한다.**
- **에이전트 본체 실측 = gpt-4o-mini** (OpenAI). Gemini-3.5-flash 는 동일 `Provider` 계약으로 스왑 가능하고 도구호출 스모크로 parity 확인했으나, 무료 5 RPM 병목으로 헤드라인 스윕은 OpenAI 로 수행. **논지는 모델 무관**(게이트는 문자열을 읽지 않고 도구 identity 로 판정).
- **코퍼스 소규모**(60 공격+2 정상, BPR 얇음), **한국어 번역 오염**(MAPS 부분번역, 자체 코퍼스 템플릿 기반).
- **Kanana P1b(난독화 붕괴) 사전등록 미달** — §4 참조. 예측(≥0.25)이 반증됨(0.1). 숨기지 않고 보고.
- **classifier_gate arm 은 교차언어로 눈먼 영어 CPU 레일로만 측정** — 한국어 가능 분류기(Kanana) 강제(P6a)는 미측정. "모든 분류기 무효"로 일반화하지 않는다.
- **spotlight arm 은 부분 구현** — before_model 지시문만 주입하며, 도구 출력이 구조체(list/dict)라 구분자 마킹(`wrap_untrusted`)은 실제 적용되지 않았다(코드 검증). theater 판정(n.s.)은 불변이나 "완전한 spotlighting"으로 일반화하지 않는다.
- **DLP×TierA 합성(서비스는 배선, eval 은 미포함)** — 서비스 런타임은 egress **사전복원**(`policy.py` 0단계: allowlist_ref 인자 to/account 를 게이트 검사 전에 원본 복원)으로 dlp_vault+tier_a 를 정상 합성한다(토큰인 채 차단되던 문제 해결됨). 다만 오프라인 `eval/dlp_eval` 은 **DLP 독립 축**(vault OFF/ON)만 측정하고 tier_a 와의 합성 arm 은 스윕에 포함하지 않았다(측정 범위의 문제이지 런타임 결함 아님).
- **Tier C 전면**(Q-LLM 격리)은 설계 명세로 제출(분기 D, `tier_c` arm 은 NotImplementedError 로 봉인).
- **재현성 범위:** 헤드라인 애블레이션은 라이브 OpenAI 호출(temp=0 근사 재현). DLP·channel_gap·R6/R7·e5·shieldgemma 는 RunPod GPU 스크립트 산출로 단일 명령에 미포함.
- **관측성·견고성(프로토타입 수준, 정직 서술):** 보안 코어(Tier A) 신뢰 경계는 코드로 실증되나 이를 감싼 런타임은 연구 프로토타입이다. 이번 검토에서 (a) 케이스 실패 격리(관측용 레일 예외가 스윕 전체를 죽이지 않고 `finish_reason="error"` 로 기록), (b) 실행된 홉이 after_tool 예외와 무관하게 트레이스에 남도록 순서 수정, (c) hop 단위 전체 트레이스(`traces.jsonl` — gate_rule·taint·rail·latency) 영속화를 **코드에 배선**했다(다음 eval 실행 시 생성. ⚠️ 커밋된 frozen `runs.jsonl` 은 배선 이전 산출이라 `traces.jsonl` 은 미동봉). **남은 한계:** 구조적 로깅·토큰/비용 계측·재시도/백오프·per-seam 지연 분해·차단율/PII유출 대시보드 부재 — "프로덕션 안전 런타임"이 아니라 **측정 가능한 연구 런타임**임을 명시한다.

## 6. 결론

> **헤드라인 범위(정직한 경계):** 본 보고서가 주장하는 핵심은 **런타임에 실제 배선되고 근거로 뒷받침된 3가지** — ① Tier A 결정적 게이트(런타임 배선 + 유일하게 방어 방향이 일관: vs 무방어 행 p=0.002 **탐색적**, post-hoc v0.2 시나리오 p=0.031(보정 시 미유의) — 통계 유의가 아니라 **구조적 차단**으로 주장), ② Kanana 채널 격차(GPU 실측), ③ RegexVault 요청스코프 DLP(런타임 배선, fail-closed) — 에 한정한다. **R6 PII NER·R7 유해·R4 Tier C·ShieldGemma는 런타임에 연결되지 않은 오프라인 탐지기 실험(부록)**이며, 특히 R6 F1은 누수 가능 상한이므로 헤드라인 근거로 쓰지 않는다.

한국어 도구 사용 에이전트에서 **강제(enforcement)는 어떤 분류기(온디바이스·Google 것 포함)가 아니라 결정적 per-tool 정책 게이트에 있어야 한다.** 분류기는 로그 전용 텔레메트리로 강등하되 유용하다 — 어디서 뚫리는지(언어·난독화) 측정하는 도구로서. SafeAgent-KR 은 이 원칙을 4-seam 런타임으로 구현하고, KoTIP-Bench 위에서 층별 애블레이션(McNemar)으로 실증했으며, 재현 가능한 코드·데이터·사전등록과 함께 제출한다.
