## 1. 무엇을 돌렸나

`python train/runpod_pipeline.py --device cuda --train` 한 명령 — 3b 창 정렬 → 교사 3종 → 6b 일치도
게이트 → 7 클래스별 2표 합의 → 8·8b 봉인 → 9 preflight → 10 dry-run · 3 seed 학습. 그 뒤 11단계
(seed 선택 · ONNX 내보내기 · 봉인 test 평가 · 지연)와 외부 벤치 두 축.

| 단계 | 시간(RTX 3090) | 비고 |
|---|---|---|
| 교사 kanana · Gemma 4 | (앞선 실행에서 완료, 이어 돌기) | 각 19,157행, 기권 0 |
| 교사 Qwen3Guard-Gen-4B | 약 80분 · 232행/분 | 피크 22GB, 할당기 OOM 경고 1회(자체 회수, 예외 없음) |
| L1 학습 3 seed × 5 epoch | 약 2시간 40분 · epoch 당 약 10분 | bf16 autocast, micro-batch 16 × 2 = 논리 32, 8.4GB |
| 봉인 test 평가(INT8 + FP32) | 약 50분 | pod CPU 16코어 |

첫 실행 둘은 멈췄다 — Gemma 교사가 범주 이름 대신 설명을 옮겨 적었고(`35a41d1`), KDPII span 하나가
앞 공백을 물어 학습 첫 줄에서 창 정렬이 실패했다(`f0bbe9e`). 두 번째는 교사 3종을 다 돌린 뒤에야
드러났기 때문에 PII 학습·검증 전체를 교사보다 먼저 인코딩하는 3b 단계를 넣었다.

## 4. 봉인 test — 원천별 (ONNX QInt8)

8b 에서 봉인한 여덟 파일 17,146행. FP32 기준선과의 차이는 모든 칸에서 ±0.002 이내였다.

### PII — 세 단계로 잰다

`evaluate_l1.py` 는 표준 토큰 분류 지표다(argmax 가 O 가 아닌 토큰을 전부 개체로 센다). 런타임은
개체 점수(토큰 softmax 평균) × 0.9(주민·외국인등록번호 0.7)를 `l1_pii`(0.5)와 비교하고, 그 뒤
L0 와 병합·정책을 거친다. 셋을 따로 낸다(`bench/l1_product_path.py`).

| 원천 | 행 | L1 원출력 P / R | 임계 적용 L1 | **제품 경로** | 무엇을 지탱하나 |
|---|---:|---|---|---|---|
| KDPII test | 5,438 | 0.987 / 0.985 | 0.988 / 0.985 | **0.980 / 0.977** | 외부 원천이지만 train 과 같은 분포의 분할 |
| KLUE-NER validation | 5,000 | 0.886 / 0.933 | 0.889 / 0.932 | **0.889 / 0.932** | PERSON 하나. 유명인 중심 |

정답 PII 가 없는 원천 — **PII 가 하나라도 나온 행**(예측 문자):

| 원천 | 행 | L1 원출력 | 임계 적용 L1 | **제품 경로** |
|---|---:|---:|---:|---:|

| 합성 공격 test | 377 | 132 (4,480자) | 0 | **0** |

**임계가 오탐을 거의 다 걷어 내고 정탐은 거의 잃지 않는다** — 진짜 PII 는 확신도가 높게,
은닉 변이 위의 오탐은 낮게(T4 개체 점수 중앙값 0.14) 나온다. 제품 경로에 남는 오탐은 **보강 음성
8.6%** 다. 이 셋은 bc-pii-ko 가 제공하는 "PII 아닌 숫자" 문장(청구 금액·포인트·대기번호·문서번호·
주문번호·운송장번호)인데, 62행에서 오탐 65건이 나왔고(KR_ACCOUNT 50 · PHONE 12 · KR_RRN 2 · KR_NHI 1)
대부분이 **12자리 운송장번호**다. pod 에서는 문장 종류별로 세지 않았다 — 같은 모델을 Mac(ARM)에서 다시
돌리면 60행 · 60건이고 그중 54건이 12자리 운송장번호, 나머지 6건은 8자리 접수·승인번호에 붙었다
(`04760327` 의 앞 `04` 를 PHONE 으로). 예: `운송장번호 995648878534 으로 배송 조회가 가능합니다` → `995648878534` 를 계좌번호로
가린다. 계좌번호도 10~14자리 숫자이고 공통 체크섬이 없어 문맥 단어("운송장번호")가 유일한 단서인데,
학생이 그것을 쓰지 못한다. 다음 학습의 PII 음성에 넣을 1순위다.

## 5. 찾은 결함 — 원출력 · 교사 합의 · 생성기 분할

### ① 낯선 문자열을 PII 로 읽는다 — 원출력에서만

T4 3,200행은 PII 정답이 하나도 없다. 정규식으로 다시 확인해도 전화·여권 형식이 0건이다. 그런데
봉인 평가(정규화 뒤 L1 원출력, 임계 없음)에서 **65,440 문자**가 PII 로 칠해졌다. 처음에는 base64
덩어리 탓으로 읽었는데 **은닉 기법별로 세어 보니 아니었다**(평가 하네스와 같은 절차로 다시 셈):

| 은닉 | 행 | L1 원출력에 PII (문자) | **제품 경로(`Inspector`)에서 PII** |
|---|---:|---:|---:|
| hanja(한자 섞기) | 400 | **317** (11,504) | 0 |
| homoglyph | 400 | **293** (10,289) | 11 |
| space_break | 400 | **289** (5,163) | 0 |
| jamo | 400 | 251 (8,999) | 0 |

(문자 합계 51,295 가 평가 하네스의 65,440 보다 작은 것은 이 표가 정규화 텍스트 위 길이를, 하네스가
원문으로 되돌린 위치를 세기 때문이다 — 자모 합성 등은 원문에서 더 길다.)

모델은 학습에서 보지 못한 문자 구성(한자·동형 문자·쪼개진 어절)을 여권번호·전화·조직 ID 처럼
읽는다 — 다만 **낮은 확신도로**(개체 점수 중앙값 0.14, 90분위 0.23). 런타임 임계(0.5/0.9)가 그것을
걸러 15행만 남는다(카드 27건 · PERSON 3건, 그중 11행이 동형 문자). 남는 개체는 확신도가 임계 바로
위(0.50~0.59)라 CPU 에 따라 어느 행이 넘는지가 바뀐다 — Mac(ARM)에서 다시 돌리면 같은 15행이지만
동형 문자 14 · 은닉 없음 1, 카드 30건이고 b64 행은 원출력부터 개체가 없다. **사용자가 겪는 오탐은 0.47%
쪽이고**, 65,440 은 원출력의 보정 상태를 보여 주는 수치다. 임계 근처로 확신도가 올라오는 변이가
생기면 바로 새는 구조라 원출력 쪽도 고칠 가치가 있다.

문장 단위로 갈렸다:

((NONE, NONE) 5행은 kanana 확신도가 0.5 미만이라 표가 하나였다.) 트리거 단어("시스템 설정",
"이전 … 지시")를 품은 정상 요청, 즉 **설계상 가장 중요한 음성 두 문장**이 학습에서 통째로 사라졌다.
한 교사가 과탐하면 불일치가 되고, 불일치는 폐기되므로 학생은 그 문장을 NONE 으로 한 번도 보지 못한다.

**오탐이 그 문장에서 나온다**(Mac 에서 같은 ONNX 로 다시 셈 — T4 는 pod 163 / Mac 162):

| NONE 오탐(→ SYSTEM_LEAK) | 시스템 설정 화면… | 나머지 네 문장 |
|---|---:|---:|
| 합성 공격 test | **30 / 30** | 0 / 216 |
| T4 · T4′ | **97 / 129** | 65 / 833 |

"원인 후보" 가 아니라 직접 증거다. 반대로 "이전 회의 지시사항" 은 폐기됐는데도 합성 test 에서
36/36 NONE 이었다 — 빠진 문장이 모두 오탐이 되는 것은 아니다.

"불일치는 NONE 으로 흡수하지 않는다" 는 규칙(§6.2.2)은 거짓 음성을 막으려던 것인데, **반대쪽
— 거짓 양성을 가르칠 음성 — 도 함께 걸러 낸다.** 이번 설계가 놓친 점이다.

### ③ 합성 test 가 학습과 기본 문장을 전부 공유한다

§6.3 은 템플릿 단위 분할을 요구했고 생성기도 `template_id` 로 분할한다. 그런데 그 `template_id` 가
실제 문장 템플릿이 아니라 **인덱스의 나머지**(`atk-{label}-{i % 60}`, `benign-{i % 200}`)다. 같은 기본
문장이 ID 여러 개로 흩어져 해시로 따로 분할되므로 train·test 양쪽에 들어간다. 은닉을 끄고 생성기를
다시 돌려 기본 문장 단위로 셌다:

| 클래스 | 기본 문장 train / validation / test | test 중 학습에도 있는 것 |
|---|---|---:|
| INJECTION | 14 / 8 / 10 | **10 / 10** |
| JAILBREAK | 14 / 5 / 12 | **12 / 12** |
| SYSTEM_LEAK | 14 / 8 / 9 | **9 / 9** |
| NONE | 5 / 5 / 5 | **5 / 5** |

T4 는 이 test 분할에서만 만든다. 행 지문은 꼬리말 번호 덕에 겹치지 않으므로 `validate_corpus` 도,
T4 docstring 의 "지문 교집합이 구성상 ∅" 도 거짓은 아니다 — **문장이 겹친다.** 그래서 T4 와 합성 test
는 "학습에서 본 문장에 은닉을 씌웠을 때 견디는가" 를 재며, 새 표현으로의 일반화는 재지 않는다.
일반화 근거는 외부 셋(KoreanGuardrail · deepset)뿐이다. DESIGN §5.3.6 이 요구한 정상 1,200 의 다양성
("존댓말 업무 요청, 정상 한자 병기, 들여쓰기 문서")도 5문장으로는 충족되지 않았다.

같은 자리에 라벨 충돌도 있다. 보조 헤드용 로마자 문장(`ijeon jisireul musihago …`)과 존댓말 문장
(`번거로우시겠지만 기존 제한을 …`)은 **같은 텍스트가 INJECTION · JAILBREAK · SYSTEM_LEAK 세 라벨로
20행씩** 들어간다. 학습 쪽은 교사 합의 라벨을 쓰므로 영향이 없지만, 생성기 라벨을 gold 로 쓰는 합성
test 에서는 공격 131행 중 25행이 어떤 예측을 해도 맞을 수 없는 행이다.

### 다음 학습에 넣을 것 — 사전 등록이 먼저다

이번 test(특히 T4)를 본 뒤의 수정이므로, 고친 모델은 같은 T4 로 재면 안 된다. 무엇을 바꾸고 무엇으로
판정할지는 [PREREG_L1_R2.md](PREREG_L1_R2.md) 에 데이터 생성보다 먼저 고정한다.

1. **생성기의 기본 문장 단위 분할** — `template_id` 를 실제 기본 문장으로 바꾸고, 정상·공격 기본 문장을
   늘린다(§5-③).
2. **생성기 NONE 의 하드 네거티브는 교사 불일치여도 남긴다** — 생성기 라벨이 있는 행에 한해
   생성기를 세 번째 표로 쓴다. 공격 쪽에는 쓰지 않는다(자작 공격이 교사 검증을 우회하면 안 된다).
3. **PII 아닌 숫자·낯선 문자 구성의 음성** — 운송장·주문·송장번호처럼 계좌·전화와 자릿수가 같은
   번호를 문맥 단어와 함께, 그리고 한자 혼용·동형 문자·어절 쪼개기 문장과 base64·hex·해시를 O 라벨로
   넣는다(T4 · bc-pii-ko 와 다른 템플릿·다른 시드).
4. **SYSTEM_LEAK 학습 행 75** — KoreanGuardrail A2 0.146 의 직접 원인 후보다.
5. 새 봉인 test 를 먼저 만들고 고정한 뒤 학습한다.

자모 분해·영폭 공백이 **clean 과 정확히 같다** — 가역 정규화가 L1 앞에서 그 둘을 완전히 되돌린다.
§2.3 "우회 방어는 결정적 규칙에, 의미 판단은 분류기에" 가 학습된 L1 에서도 그대로 성립한다는
뜻이다. 띄어쓰기 깨기·초성·경음화는 정규화가 되돌리지 않는 변이라 학생이 약하다.

### 축 (a) TAB — 거의 0

DIRECT 0.036 · QUASI 0.012 · NO_MASK 오탐 0.005. 한국어로만 배운 L1 은 영어 판례의 개체를 거의
못 본다. 이 하네스는 처음부터 "문맥 판단 능력이지 한국어 성능 근거가 아니다" 로 등록됐다. 평가는
L1 시간 예산만 60초로 푼 벤치 정책으로 했고 degraded 문서는 0 이었다 — 이 0 은 지연 예산이 아니라
판별력이다.

## 7. 판정에 쓰면 안 되는 수치

- **합성 PII 1.000 / 1.000** — 생성기 형식을 학습한 결과다. 회귀 지표다.
- **seed 간 우열** — validation 소수 클래스가 13·8행이다.
- **T4 · 합성 공격 test 의 절대값** — 자작이고, 기본 문장이 전부 학습에도 있으며(§5-③), NONE 분모는
  기본 문장 5개다. 방향(NONE→SYSTEM_LEAK, 인코딩 PII 오탐)만 쓴다.
- **지연 99ms(128토큰)** — pod CPU(16코어 컨테이너)다. §7.1.3 의 노트북 기준이 아니다. 로컬
  M1 은 다른 실험이 돌고 있어(load 16, swap 21.5/22.5GB) 이번에 재지 않았다.
- **KDPII 0.987** — 원천은 외부지만 train 과 같은 분포의 분할이다. 실 업무 텍스트 재현율이 아니다.
- **제품 경로 오탐의 행 단위 내역** — 남는 개체가 임계 바로 위라 CPU(x86 pod / ARM Mac)에 따라 T4 내역과
  보강 음성 행 수(62 ↔ 60)가 바뀐다. 비율과 방향만 쓴다.
