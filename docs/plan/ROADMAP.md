## 원칙

**주차별 검증 기준은 외부에서 확인 가능한 형태여야 한다.** "구현했다"가 아니라 "이 명령을 실행하면 이 산출물이 나온다"로 쓴다. 구 프로젝트는 일정표에 D0~D6 완료를 ✅로 표시했지만 git 이력상 그 기간의 커밋이 존재하지 않았다. 같은 일이 반복되지 않도록 검증 기준을 파일·테스트·수치로 고정한다.

**미달 시 잘라내는 순서**: 스트레치 → 정성 산출물 → 축 B(벤치마크 확장) → 축 C의 고급 기능(trifecta·핀닝) 순. **축 A(PII 스위트 + 볼트)와 축 C의 최소 형태(MCP 게이트웨이가 실제로 차단한다)는 마지막까지 지킨다** — 이 둘이 헤드라인 H1·H2를 지탱한다. **잘라낸 것은 이 문서에 남긴다** — 구 프로젝트가 "절대 자르지 않음"으로 지정한 과차단 프로브를 조용히 미실행으로 남긴 전례가 있다.

## W3 — 가드 캐스케이드 · 흐름 판정 · 데모 에이전트

**목표**: 모델 기반 탐지가 예산 안에서 돌고, **다단계 유출이 구조적으로 차단되며**, 보호 대상 에이전트가 붙는다.

| 작업 | 내용 |
|---|---|
| L1-PII | `privacy-filter-korean` (CPU). 정규식 스위트와의 보완 관계 확인 |
| L1-INJ | `kanana-safeguard-prompt-2.1b`. GPU 부재 시 휴리스틱 폴백 + **폴백 사실 로그 기록** |
| **도구 핀닝** | JCS(RFC 8785) 정규화 + SHA-256. `tools/call` 직전 재검증(TOCTOU), 업스트림 `ttlMs` 상한 |
| **description 스캔** | `inputSchema`/`outputSchema` **재귀 walk**(`$ref`·`allOf` 내부 포함), NFKC + 제로위드 제거, 권위 마커·은폐 지시·크로스 툴 참조 시그니처 |
| **Lethal Trifecta** | private data / untrusted content / external comm 세션 추적. 3요소 성립 시 판정 ([AGENT_SYSTEM §6](AGENT_SYSTEM.md#6-lethal-trifecta--동적-흐름-판정)) |
| **capability 다운그레이드** | `clientCapabilities`에서 `sampling` 제거 → 준수 서버는 요청 불가 |
| provenance | `taint.py`의 **value-provenance** 이식 |
| **데모 에이전트** | Google ADK + Gemini. `McpToolset` url을 게이트웨이로 교체 |
| **R1 — 한국 PII NER 학습** | 트랙 A(A.X-Encoder 풀 FT) / 트랙 B(privacy-filter LoRA) 병행 후 선택. **로컬 메모리 15배 차이라 A가 유리** ([MODEL_AND_TRAINING §5.2](MODEL_AND_TRAINING.md#52-r1--한국-pii-ner)) |
| **R2 — 인젝션 distillation** | kanana 2.1b 교사 → A.X-Encoder 0.1B 학생. **2B를 노트북 인라인에 둘 수 없어서 필수** |
| 레이턴시 측정 | **하드웨어 프로파일 P1~P3 선언 후** 심별 p50/p95 |

**게이트 판단 3건 — 결과를 이 문서에 기록한다**
1. **R1 트랙 A vs B** — 트랙 B가 F1에서 유의하게 이기지 않으면 메모리 15배 유리한 A를 택한다
2. **R2 학생의 허용 저하폭** — 교사 대비 어느 정도까지 떨어지는 것을 받아들일지
3. **추가 학습 필요 여부** — 문맥 의존 엔티티에서 재현율이 목표에 미달하는가

**검증 기준**
- [ ] 하드웨어가 명시된 레이턴시 실측표. 입력 p50 < 100ms, 출력 p50 < 150ms **달성/미달을 정직하게** 기록
- [ ] 예산 초과 시 무엇을 뺐는지 기록
- [ ] **직결 / 경유 두 구성 비교** — 직결에서 도구가 실행되고 경유에서 차단됨을 재현 스크립트로 확인
- [ ] rug pull 시나리오(승인 후 description 변조)를 핀닝이 잡음
- [ ] trifecta 3요소 성립 시 차단, 2요소면 통과
- [ ] **단방향 rehydrate 테스트** — internal 도구 왕복 후 모델이 받은 텍스트에 원본 PII 부재 (결함 4)
- [ ] ADK + LiteLLM + MCP 조합 이슈(adk-python #929, #3906) 검증 결과 기록
- [ ] 게이트 판단 3건 기록
- [ ] **하드웨어 프로파일 P1(8GB 노트북)에서 게이트웨이가 동작**함을 확인

|---|---|
| **OAuth 2.1 Resource Server** | 멀티테넌트 배포의 전제. v1은 단일 테넌트로 미룬 항목 ([AGENT_SYSTEM §8.6](AGENT_SYSTEM.md#86-인가--게이트웨이는-독립-resource-server다)) |
| **modern era(2026-07-28) 완전 지원** | W2에서 legacy로 범위를 좁혔다면 여기서 확장 |
| **Qwen3Guard-Stream** | `during_call` 훅으로 스트리밍 중 토큰 단위 차단. 다른 어떤 가드도 못 하는 것 |
| **Presidio 업스트림 PR** | 확인된 한국어 결함 2건 + 한국 recognizer 스위트. 커뮤니티 이관 후 수용 여부가 불확실하므로 부가 목표 |
| 가명 치환 (FPE형) | `홍길동` → `김민준` 자연스러운 치환으로 LLM 품질 유지 |

## 평가 원칙 5조

[기획서 §5.1](기획서.md#51-평가-원칙-5조)과 동일. 여기 다시 두는 이유는 매주 검증 기준을 쓸 때 참조해야 하기 때문이다.

1. **평가 설계 고정** — W4 착수 전 별도 커밋. "사전등록"이라는 용어는 쓰지 않는다.
2. **재현율 옆에 항상 FPR** — 예외 없다.
3. **동어반복 금지** — 헤드라인 지표는 "이 시스템이 질 수 있는가" 테스트를 통과해야 한다.
4. **n은 군집 단위로** — 시나리오 × 스타일의 곱을 행 수로 세지 않는다.
5. **레이턴시는 하드웨어 선언 후** — 사양 없는 지연 수치는 보고하지 않는다.
