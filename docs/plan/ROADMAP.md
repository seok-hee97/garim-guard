## 원칙

**주차별 검증 기준은 외부에서 확인 가능한 형태여야 한다.** "구현했다"가 아니라 "이 명령을 실행하면 이 산출물이 나온다"로 쓴다. 구 프로젝트는 일정표에 D0~D6 완료를 ✅로 표시했지만 git 이력상 그 기간의 커밋이 존재하지 않았다. 같은 일이 반복되지 않도록 검증 기준을 파일·테스트·수치로 고정한다.

**미달 시 잘라내는 순서**: 스트레치 → 정성 산출물 → 축 C(tool-call) → 축 B(벤치마크 확장). 축 A(PII 스위트 + 볼트)는 마지막까지 지킨다. **잘라낸 것은 이 문서에 남긴다** — 구 프로젝트가 "절대 자르지 않음"으로 지정한 과차단 프로브를 조용히 미실행으로 남긴 전례가 있다.

**목표**: 게이트웨이 골격 위에서 한국 고유 PII 8종이 체크섬 검증과 함께 탐지되고, 마스킹과 복원이 왕복한다.

| 작업 | 내용 |
|---|---|
| LiteLLM 스켈레톤 | `GarimGuardrail(CustomGuardrail)` 서브클래스 + `pre_call` / `post_call` 훅 골격. 버전 lock |
| 볼트 이식 | `src/dlp/vault.py`의 `RegexVault`를 새 구조로 이식 ([ASSET_REUSE.md](ASSET_REUSE.md)) |
| PII recognizer 8종 | 주민등록번호·외국인등록번호·여권·운전면허·사업자등록번호·법인등록번호·계좌번호·카드번호. **각각 체크섬 또는 사전 검증 포함** ([ARCHITECTURE §5.1](ARCHITECTURE.md#51-엔티티-8종과-체크섬)) |
| 한국어 문맥 단어 사전 | Presidio confidence 보정용 |
| 조사 처리 설계 | [ARCHITECTURE §5.2](ARCHITECTURE.md#52-가역-마스킹-볼트)의 세 경우 분해에 따라 방식 결정 |

**선결 과제 (블로커)**
- **KDPII 라이선스 확인.** 실패하면 PII 평가셋을 전량 합성으로 대체하고 데이터 카드에 명시한다 ([기획서 R1](기획서.md#6-예상-문제점-및-대처-방안))
- **형태소 분석기 라이선스 결정.** kiwipiepy는 LGPL — 대안 3개 비교 후 문서화 ([기획서 R2](기획서.md#6-예상-문제점-및-대처-방안))

**검증 기준**
- [ ] 엔티티 8종 각각에 대해 유효/무효 체크섬/형식 유사 비-PII 3종 케이스가 있는 골든 테스트 통과
- [ ] `redact → rehydrate` 왕복이 조사 결합 케이스를 포함해 무손실 (테스트로 고정)
- [ ] 토큰 관용 매칭의 허용 범위가 테스트로 명시됨 (대소문자·공백 어디까지 복원하는가)

## W2 — 정책 엔진과 감사

**목표**: 무엇을 탐지했을 때 어떻게 할지가 선언적으로 결정되고, 그 판정이 규제 조항에 매핑된 로그로 남는다.

| 작업 | 내용 |
|---|---|
| 정책 테이블 엔진 | YAML 스키마 확정 + `엔티티 × 라우트/그룹 → allow/mask/warn/block` 매칭. 기본값 `mask` |
| 매칭 우선순위 규칙 | [ARCHITECTURE §10](ARCHITECTURE.md#10-미결-사항)의 미결 사항 결정 |
| 감사 로그 | JSONL + JSON Schema 고정. 원문 미저장(해시), `fallback_used`, `latency_ms` 분해 |
| 규제 매핑표 | 개인정보위 안내서 4단계 / 금융분야 AI 가이드라인 7원칙 / 인공지능 기본법 기록보관 → `regulatory_tags[]` |
| 관리·감사 API | FastAPI 사이드카. 정책 조회, 감사 조회, `warn` 승인 큐 (`hitl.py` + `server.py` 패턴 이식) |

**검증 기준**
- [ ] 4모드 × 8엔티티 매트릭스 테스트 통과 (32조합 전부)
- [ ] 감사 이벤트가 JSON Schema 검증을 통과하고, **원문 PII가 로그에 나타나지 않음**을 테스트로 확인
- [ ] 규제 매핑표가 문서로 존재하고 태그가 실제 이벤트에 붙음
- [ ] `warn` → 승인 → 통과 / `warn` → 타임아웃 → 거부 두 경로가 통합 테스트로 확인됨
- [ ] 요청자 ≠ 승인자 강제 (자기승인 거부) 테스트 통과

## W3 — 가드 캐스케이드와 tool-call DLP

**목표**: 모델 기반 탐지가 레이턴시 예산 안에서 동작하고, tool call 인자가 검사된다.

| 작업 | 내용 |
|---|---|
| L1-PII | `privacy-filter-korean` 통합 (CPU). 정규식 스위트와의 보완 관계 확인 |
| L1-INJ | `kanana-safeguard-prompt-2.1b` 입력 레일. GPU 부재 시 휴리스틱 폴백 + **폴백 사실 로그 기록** |
| L3 비동기 | `kanana-8b` / `siren-8b` 감사 라벨링 (GPU 있을 때만) |
| tool-call 검사 | assistant `tool_calls` 인자 PII 스캔 + egress allowlist. tool 롤 메시지 비신뢰 태깅 |
| provenance | `taint.py`의 `Tainted` 래퍼 + **value-provenance** 검사 이식 ([ARCHITECTURE §6.2](ARCHITECTURE.md#62-provenance-추적)) |
| 레이턴시 측정 | 하드웨어 사양 선언 후 계층별 p50/p95 |

**게이트 판단 — privacy-filter 추가 파인튜닝 여부**
조건: 문맥 의존 항목(조사가 붙은 한국식 성명, 도로명·지번 혼합 주소)에서 재현율이 목표에 미달할 때. 방식과 판단 기준은 [기획서 §4.3](기획서.md#43-파인튜닝--조건부-경로).
→ **판단 결과를 이 문서에 기록한다** (진행 / 미진행 + 사유).

**검증 기준**
- [ ] 하드웨어 사양이 명시된 레이턴시 실측표. 입력 p50 < 100ms, 출력 p50 < 150ms 달성 여부를 **달성/미달로 정직하게** 기록
- [ ] 예산 초과 시 무엇을 뺐는지(병렬화 / 조기종료 / 비동기 이동) 기록
- [ ] tool 인자에 포함된 PII가 마스킹·거부되는 데모 (재현 가능한 스크립트)
- [ ] tool 반환값에서 파생된 값이 다음 tool 인자로 흘렀을 때 value-provenance가 잡는 케이스 테스트
- [ ] 파인튜닝 게이트 판단이 문서에 기록됨

## W4 — KoTIP-v2와 양성 코퍼스

**목표**: 평가할 수 있는 데이터가 생기고, 그 구조가 정직하게 문서화된다.

> **W4 착수 전에 "평가 설계 고정" 커밋을 먼저 만든다.** 지표 목록, n의 정의(군집 수), 통계 방법, 베이스라인을 담은 문서를 별도 커밋으로 남긴 뒤 데이터 생성을 시작한다.

| 작업 | 내용 |
|---|---|
| 시나리오 확장 | 12개 이상 시나리오 (v0.1은 2개였다). 군집 구조를 데이터 카드에 명시 |
| 한국어 우회 벡터 | 기존 6종(`eval/obfuscate.py`) + 자모분해·초성체·로마자·한자혼용·조사파괴·존댓말 사회공학·호환자모 |
| 양성 코퍼스 | **공격과 동수 이상.** 정상 업무 맥락에 PII 형식 유사 문자열(주문번호·사번·제품 시리얼) 의도적 포함 |
| PII 평가셋 | KDPII(라이선스 확인 시) 또는 합성. 템플릿 단위 holdout |
| 오염 검사 | `eval/check_contamination.py` 재사용 → GREEN 확인 |
| 데이터 카드 | 곱 구조, 독립 군집 수, benign 비율, 제외 조합과 사유, 생성 코드 경로, 실제 개인정보 미포함 선언 |

**검증 기준**
- [ ] "평가 설계 고정" 커밋이 데이터 생성 커밋보다 앞섬 (git 이력으로 확인 가능)
- [ ] 데이터 카드에 **독립 군집 수**가 명시됨 (행 수가 아니라)
- [ ] benign 개수 ≥ 공격 개수
- [ ] 뮤테이터가 판정 앵커를 파괴하는 조합이 제외되고 그 사유가 기록됨 (v0.1에서 homoglyph·jamo·base64가 카나리 주소까지 변형해 무방어에서도 0이 나온 문제)
- [ ] 오염 검사 GREEN

## 평가 원칙 5조

[기획서 §5.1](기획서.md#51-평가-원칙-5조)과 동일. 여기 다시 두는 이유는 매주 검증 기준을 쓸 때 참조해야 하기 때문이다.

1. **평가 설계 고정** — W4 착수 전 별도 커밋. "사전등록"이라는 용어는 쓰지 않는다.
2. **재현율 옆에 항상 FPR** — 예외 없다.
3. **동어반복 금지** — 헤드라인 지표는 "이 시스템이 질 수 있는가" 테스트를 통과해야 한다.
4. **n은 군집 단위로** — 시나리오 × 스타일의 곱을 행 수로 세지 않는다.
5. **레이턴시는 하드웨어 선언 후** — 사양 없는 지연 수치는 보고하지 않는다.
