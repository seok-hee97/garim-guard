**한 줄 정의**: 한국 기업용 오픈소스 GenAI DLP 게이트웨이. 프롬프트와 tool-call 양쪽에서 한국어 개인정보를 체크섬 검증으로 탐지하고 가역 마스킹하며, **오탐률(FPR)까지 공개 벤치마크로 증명한다.**

---

## 1. 프로젝트 개요

### 1.1 배경 및 필요성

**(a) 시장에는 제품이 있는데 검증 수단이 없다.**
국내에 기업용 생성형 AI 데이터 보안 제품이 최소 8종 존재한다 — 참고 솔루션인 안랩클라우드메이트 SecureBridge(2025-06 출시, 2026-07 과기정통부·KISA 우수 정보보호기술 지정)를 비롯해 파수 AI-R DLP, 지란지교 OfficeKeeper, 소만사 WebKeeper, 컴트루 Sphinx AI, 윈스 SNIPER AIVAX 등이다([MARKET_RESEARCH §2](MARKET_RESEARCH.md#2-국내-경쟁-지형)). 그런데 **이 중 오탐률(false positive rate)을 수치로 공개한 제품은 하나도 없고, 한국어 프롬프트 DLP의 공개 비교 벤치마크도 존재하지 않는다.** 구매자는 "정확하다"는 벤더 주장을 검증할 방법이 없고, 현장에서는 과도한 차단이 업무 마찰과 경보 피로를 낳아 결국 DLP가 우회 대상이 된다는 지적이 나온다.

**(b) 한국어 PII를 다루는 수단은 클라우드에만 있다.**
Microsoft Presidio는 공식 문서가 "기본 설정에는 영어용 recognizer와 모델만 포함"이라 명시한다. OpenAI Privacy Filter의 엔티티 8종에도, Meta Llama Guard 3/4와 Prompt Guard 2의 공식 지원 언어에도 한국어가 없다. 레퍼런스였던 LLM Guard는 2026-07-09 아카이브됐다.

반면 **클라우드에는 있다.** Google Cloud Sensitive Data Protection은 한국 infoType 6종(`KOREA_RRN`, `KOREA_PASSPORT`, `KOREA_ARN`, `KOREA_BRN`, `KOREA_DRIVERS_LICENSE_NUMBER`, `KOREA_NHI_NUMBER`)을 내장하고, Model Armor는 공식 지원 언어에 한국어를 명시한다. **그러므로 이 프로젝트의 갭 정의는 "탐지기가 없다"가 아니라 "데이터를 내보내지 않고 쓸 수 있는 탐지기가 없다"이다.** 두 제품 모두 프롬프트를 클라우드로 전송하며, Model Armor의 서울 리전 데이터 레지던시는 릴리스 노트에서 확인되지 않는다. 개인정보보호법이 2014년 8월 이후 **법적 근거 없는 주민등록번호 처리를 동의 여부와 무관하게 금지**(유출 시 최대 5억원 과징금)한다는 점을 고려하면, 주민번호를 클라우드로 보내는 구성 자체가 검토 대상이 된다. 상세는 [MARKET_RESEARCH §6.1.2](MARKET_RESEARCH.md#612-google-cloud의-한국어-보안-제품--실질-경쟁자).

남는 공백은 구체적이다. 한국 고유 식별자를 **체크섬 검증까지 포함해 온프렘에서** 다루는 오픈소스가 없고(SDP에는 법인등록번호도 없다), 한국어 가역 마스킹에서 조사 결합(`홍길동이` → `<PERSON_1>이`)을 처리하는 구현이 없다.

**(c) 공격 표면은 이미 tool-call로 이동했는데 방어는 프롬프트에 머물러 있다.**
2026년 글로벌 AI 보안 제품의 발표는 예외 없이 에이전트·MCP 중심이다. MCPTox 벤치마크는 실제 MCP 서버 45개 대상에서 tool description 포이즈닝의 공격 성공률이 60~72%임을 보고했고, Microsoft는 2026-06-30 공식 블로그로 오염된 tool description이 에이전트의 데이터 유출을 유발한다고 경고했다. 그러나 **어떤 오픈소스 게이트웨이도 tool call *인자* 안의 PII를 검사하거나, tool 결과로 들어온 비신뢰 데이터가 다음 tool call로 유출되는 경로를 추적하지 않는다.** 국내 제품 중에서는 윈스만 MCP 보안을 명시한다.

**(d) 규제가 감사 로그를 법적 요구사항으로 만들었다.**
인공지능 기본법이 2026-01-22 전면 시행되어 투명성·안전성·기록보관 의무가 생겼고, 개인정보보호위원회의 「생성형 AI 개발·활용을 위한 개인정보 처리 안내서」(2025-08), 금융분야 AI 가이드라인 개정안(2026-06-22 시행), N2SF 국가망보안체계의 생성형 AI 활용 모델까지 요구가 겹친다([MARKET_RESEARCH §5](MARKET_RESEARCH.md#5-규제-앵커--기능-번역)). 특히 N2SF와 금융권 요건은 **탐지 엔진 자체가 어디서 도는가**를 묻는데, 국내 벤더 대부분이 "LLM 기반 탐지"라고만 하고 그 LLM의 위치를 밝히지 않는다.

### 1.2 프로젝트 목표

1. **한국 고유 식별자 8종을 체크섬 검증까지 포함해 탐지하고, 조사 결합을 처리하는 가역 마스킹으로 보호하는 게이트웨이**를 구현한다.
2. **tool call 인자와 tool 반환값까지 DLP 경계를 확장**해, 프롬프트만 보는 기존 제품이 놓치는 유출 경로를 막는다.
3. **한국어 고유 우회 벡터를 포함한 공개 벤치마크(KoTIP-v2)를 구축**하고, 재현율과 **오탐률을 같은 표에** 실어 공개한다. 이 시장에서 아무도 하지 않는 것이다.
4. 탐지 모델은 전부 로컬에서 구동하고 라이선스를 전수 검증해, 폐쇄망·금융·공공 요건에 부합함을 설계로 보인다.

### 1.3 차별화 축

시장 갭 5개([MARKET_RESEARCH §4](MARKET_RESEARCH.md#4-시장-갭--본-프로젝트의-좌표)) 중 솔로 5주에 실제로 완결 가능한 것을 골랐다.

| 축 | 성격 | 대응 갭 | 채택 근거 |
|---|---|---|---|
| **A. 한국형 PII 스위트 + 가역 볼트** | 제품 | ①④ | 기존 자산 재사용률이 가장 높다(`src/dlp/vault.py`, `recognizers_ko.py`, 확인된 Presidio 한국어 결함 2건). Presidio 업스트림 기여까지 이어질 수 있는 유일한 축이다 |
| **B. 한국어 인젝션·우회 벤치마크** | **평가 인프라** | ②⑤ | `eval/obfuscate.py`의 뮤테이터 6종과 KoTIP v0.1 60건을 시드로 쓸 수 있다. 갭 ②(코퍼스 부재)와 ⑤(FPR 미공개)를 동시에 메우며, 구 프로젝트가 실패한 지점(동어반복 지표·작은 n·FPR 미측정)의 직접적 교정이다 |
| **C. tool-call / MCP DLP** | 제품 | ③ | 글로벌 OSS에도 공백이고 SecureBridge조차 다루지 않는다. 그리고 구 프로젝트의 TierAGate·taint·4-seam 경험이 정확히 이 층으로 이식된다 — 피벗이 폐기가 아니라 **재배치**가 되는 지점이다. ⚠️ **이 축은 MCP 게이트웨이라는 두 번째 심을 요구한다** — LLM 프록시 하나로는 도구 실행 경로에 없어서 강제력이 생기지 않는다([AGENT_SYSTEM §1.1](AGENT_SYSTEM.md#결함-1--제품-축-c가-구조적으로-강제력이-없다-치명적)) |

**B를 제품 축이 아니라 평가 축에 둔 이유**: 세 개를 전부 제품으로 만들면 5주에 세 프로젝트를 하는 셈이다. B는 A와 C의 성능을 증명하는 인프라로 기능하게 하고, 산출물(코퍼스·벤치마크)만 공개한다.

**Shadow AI 브라우저 확장을 제외한 이유**: 기술 스택이 다르고(JS/브라우저 확장), 상용 제품의 1,200~6,000개 앱 카탈로그는 조직 규모의 문제이며, 게이트웨이 서사와의 결합이 약하다.

### 1.4 범위 (In / Out)

게이트웨이는 **심(seam) 두 개**로 구성되고 — LLM 호출 경계와 도구 실행 경계 — **사용자의 클라이언트 PC에서 단일 프로세스로 돈다.**

배포를 로컬 우선으로 정한 이유는 논지의 정합성 때문이다. "탐지는 로컬에서, 생성만 외부로"가 핵심 주장인데 게이트웨이가 서버에 있으면 그 서버 운영자는 원문 PII를 본다. 클라이언트에서 돌면 **원문을 보는 주체가 사용자 본인뿐**이고, 패킷 캡처로 증명할 수 있다. 상세는 [MODEL_AND_TRAINING §1](MODEL_AND_TRAINING.md#1-배포-모델-재정의--로컬-우선).

대가는 명확하다. **조직 차원의 강제가 약해진다** — 사용자가 끌 수 있다. 이건 "IT가 전사에 강제하는 통제"가 아니라 "개발자·분석가가 자기 PC에서 켜는 안전장치"이고, SecureBridge가 전자라면 이건 후자다.

| In — 이 프로젝트가 하는 것 | Out — 하지 않는 것 |
|---|---|
| **[심 1]** OpenAI 호환 LLM 프록시 (LiteLLM 기반) | Shadow AI 앱 카탈로그·식별 |
| **[심 2]** **MCP 게이트웨이** — 도구 실행 경계의 실제 차단 지점 | 브라우저 확장 / 엔드포인트 에이전트 |
| 두 심이 공유하는 **세션 스코프 볼트·오염 원장** | 네트워크 인라인 SSL 인터셉션, SASE/PoP |
| 한국 고유 PII 8종 탐지 + 체크섬 검증 (주민등록번호·외국인등록번호·여권·운전면허·사업자등록번호·법인등록번호·계좌번호·카드번호) | 이미지 OCR, HWP·HWPX 파일 파싱 |
| 조사 결합을 처리하는 가역 마스킹 (단방향 rehydrate) | 완성형 웹 관리 콘솔 (감사는 JSONL + CLI) |
| 도구 신뢰 등급 4종 + **Lethal Trifecta 흐름 판정** | 다국어 (한국어 + 영어만) |
| tool description 핀닝(JCS+SHA-256) + 포이즈닝 스캔 | 프로덕션 HA·멀티리전 |
| allow / mask / warn / block 4모드 정책 엔진 | 자체 유해성 분류 모델 학습 (Kanana를 이길 수 없음) |
| 규제 태그가 붙은 감사 로그 스키마 | **OAuth 2.1 Resource Server 전체 구현** — v1은 단일 테넌트 전제, 요구사항만 문서화 |
| KoTIP-v2 벤치마크 + FPR 리포트 | MCP를 통과하지 않는 도구 (에이전트의 직접 HTTP 호출) |
| Google ADK 데모 에이전트 + 오염된 MCP 서버 | 프롬프트 인젝션 완전 차단 (탐지는 보조 신호) |
| Gemini 3.6 Flash + Gemma 4 로컬 데모 | |

| **사전등록** | PREREGISTRATION.md를 결과와 같은 커밋에 추가, P5 위반 후에도 결론 유지 | 용어를 버리고 **"평가 설계 고정"** — W4 착수 전 별도 커밋 |

### 1.6 적용 분야

국내 중소·중견기업의 보안·개인정보 담당 조직, 폐쇄망 또는 N2SF 적용 대상 공공기관, 상용 제품 도입 전 PoC가 필요한 플랫폼 엔지니어. 포트폴리오 관점의 실제 독자는 Safety AI·LLM 보안 직군의 기술 평가자다.

### 1.7 프로젝트명

**가림(Garim) Gateway** — '가리다(mask)'에서 온 한국어 네이티브 이름으로, 제품이 하는 일을 그대로 서술한다. 상표·도메인 확인은 미결 사항이며 [ROADMAP의 결정 대기 절](ROADMAP.md#결정-대기-open-questions)에 기록했다.

## 2. 목표 및 성공 지표

### 2.1 주요 목표

1. 한국 고유 식별자에 대해 정규식 단독 대비 **오탐을 유의하게 줄이면서** 재현율을 유지한다 (체크섬 + 문맥 단어의 효과 측정).
2. 가역 마스킹이 조사가 결합된 한국어 문장에서 **왕복 무손실**로 동작한다.
3. tool call 인자에 포함된 PII가 외부 도구로 나가기 전에 차단·마스킹된다.
4. 게이트웨이의 동기 경로가 **업계 레이턴시 예산 안에** 들어간다.

### 2.2 정량 지표

지표를 **헤드라인 2개**와 보조로 나눈다. 재검토에서 지표 8개를 5주에 다 측정하려면 평가에만 2주가 든다는 판단이 있었다. 헤드라인은 결론을 지탱하는 것만 남기고, 나머지는 보조로 강등한다.

| # | 지표 | 무엇을 증명하는가 | 측정 방법 |
|---|---|---|---|
| **H1** | **엔티티별 PII F1 + FPR** — 8종 각각, **반드시 같은 표에** | 축 A. 국내 어느 벤더도 FPR을 공개하지 않는다 | 합성 평가셋(+KDPII), 템플릿 단위 holdout. 양성 코퍼스는 공격과 동수 이상 |
| **H2** | **tool-call 층 실차단율 + 정상 업무 오차단율** | 축 C. 게이트웨이 경유 구성과 직결 구성을 비교 | [AGENT_SYSTEM §7](AGENT_SYSTEM.md#7-유출-경로--무엇이-막히고-무엇이-뚫리는가)의 경로 P1~P8 |

H1의 단일 평균은 보고하지 않는다 — 엔티티마다 난이도가 다르고 평균은 그것을 감춘다. 구 프로젝트의 span F1 0.9845는 row-level random split의 누수 가능 상한이었으므로 같은 방식을 쓰지 않는다.

**보조 — 헤드라인을 해석하는 데 필요한 것**

| # | 지표 | 비고 |
|---|---|---|
| S1 | 정규식 단독 대비 FPR 감소 | **예측값이 있다**: 체크섬은 형식만 맞는 무작위 숫자열의 약 90%를 걸러내므로 상한이 약 10배다([AGENT_SYSTEM §4](AGENT_SYSTEM.md#4-한국형-pii와-체크섬--축-a의-정량-근거)). 실측이 예측에서 크게 벗어나면 코퍼스나 구현을 의심한다 |
| S2 | 동기 경로 레이턴시 p50 / p95 (심 2개 각각) | 입력 p50 < 100ms, 출력 p50 < 150ms. 하드웨어 사양 선언 후 |
| S3 | 인젝션 탐지 재현율 | 목표값 없음. 인젝션 탐지는 보조 신호이지 강제 경계가 아니다 |
| S4 | 벤치마크 커버리지 — **독립 군집 수** | 행 수가 아니라 군집 수로 보고 |

**테스트로 고정하고 지표로는 보고하지 않는 것**: 가역 마스킹 왕복 정합성, 세션 스코프 coreference, 단방향 rehydrate. 이들은 "몇 %"가 아니라 "되거나 안 되거나"이므로 지표가 아니라 통과/실패 테스트다.

### 2.3 정성 지표

- 규제 매핑 정책 템플릿 3종(개인정보위 안내서 / 금융분야 AI 가이드라인 / N2SF) 작성 및 감사 로그 `regulatory_tags[]`와의 연결 확인
- Gemini 업스트림 + Gemma 로컬 두 경로 모두에서 데모 시나리오 통과
- 한계 절이 존재하고, 측정하지 못한 것을 명시적으로 열거

## 3. 벤치마크·평가셋 구축

> TEMP.md 양식의 "3. 데이터 수집 및 전처리"에 해당한다. 본 프로젝트는 학습 데이터가 아니라 **평가 데이터**를 구축하므로 그렇게 재해석했다.

### 3.1 데이터 출처와 라이선스

| 데이터 | 용도 | 라이선스 | 상태 |
|---|---|---|---|
| **KDPII** (~53,778건 한국어 대화형 PII) | PII 평가셋 | 확인 필요 (Zenodo/IEEE) | **W1 선결 과제** — 확인 실패 시 전량 합성으로 대체 |
| 합성 PII 코퍼스 | PII 평가셋 보강 | 자체 생성 (실제 개인정보 미사용) | 유효 체크섬 / 무효 체크섬 / 형식 유사 비-PII 3종 구성 |
| **KoTIP v0.1** (구 프로젝트 산출, 공격 60건) | KoTIP-v2 시드 | 자체 | `data/kotip/v0.1/` 존치 |
| `korean-guardrail-dataset` 인젝션 파트 (5,059건, 대부분 번역본) | **held-out 검증 전용** | 혼재 — 항목별 확인 필요 | 자작 벤치마크의 자기편향을 견제하는 외부 셋 |

**실제 개인정보는 어떤 경로로도 저장소에 포함하지 않는다.** 모든 PII 예시는 합성이며, 주민등록번호는 유효 체크섬을 갖되 존재하지 않는 생년월일·지역코드 조합을 사용한다.

### 3.2 KoTIP-v2 설계

구 KoTIP v0.1의 구조적 결함 세 가지를 교정한다.

| v0.1의 문제 | v2의 교정 |
|---|---|
| 공격 60건이 실질 **10군집**(2 시나리오 × 5 스타일)이었는데 n=60처럼 보고 | **12개 이상 시나리오**로 확장하고 군집 구조를 데이터 카드에 명시. 통계는 군집 단위로만 |
| benign이 **2건** — 과차단 판별력 없음 | **공격과 동수 이상의 benign 코퍼스.** 정상 업무 맥락에서 PII 형식과 유사한 문자열(주문번호, 사번, 제품 시리얼)을 의도적으로 포함 |
| homoglyph·jamo·base64 뮤테이터가 카나리 주소까지 변형해 **무방어에서도 0** → 페어드 신호 없음 | 뮤테이터를 공격 페이로드에만 적용하고 판정 앵커는 보존. 적용 불가한 조합은 데이터 카드에 제외 사유와 함께 기록 |

**한국어 고유 우회 벡터** (갭 ②의 핵심 — 기존 `eval/obfuscate.py`의 6종을 확장):

| 분류 | 예 |
|---|---|
| 자모 분해 | `무시해` → `ㅁㅜㅅㅣㅎㅐ` |
| 초성체 | `ㅁㅅㅎ` |
| 로마자 표기 | `musihae` |
| 한자 혼용 | `無視` |
| 조사·띄어쓰기 파괴 | `이 전 지 시 무 시` |
| 존댓말 사회공학 | "죄송하지만 상무님 지시로…", "감사팀 요청입니다" |
| 유니코드 한글 호환자모 (U+3130~) / 전각 문자 | — |
| 기존 6종 (base64, homoglyph, emoji_smuggle, unicode_tag, zero_width, jamo_split) | `eval/obfuscate.py` 재사용 |

### 3.3 오염 검사

구 프로젝트의 `eval/check_contamination.py`(도메인 중복 + n-gram Jaccard)를 재사용해, 평가셋과 학습에 쓰인 데이터 간 중복을 GREEN 판정으로 확인한 뒤에만 결과를 보고한다.

### 3.4 데이터 카드

`data/kotip/v2/DATA_CARD.md`에 다음을 명시한다: 시나리오·스타일·난독화의 곱 구조, **독립 군집 수**, benign 대 공격 비율, 제외된 조합과 그 사유, 생성 코드 경로, 라이선스, 실제 개인정보 미포함 선언.

## 4. 모델·컴포넌트 선정 및 통합 전략

> TEMP.md 양식의 "4. 모델 선정 및 파인튜닝 전략"에 해당한다. 본 프로젝트는 기존 모델을 학습하기보다 **선정·조합**하는 것이 핵심이므로 그렇게 재해석했다. 파인튜닝은 §4.3의 조건부 경로로 둔다.

### 4.1 선정 결과와 근거

| 역할 | 채택 | 라이선스 | 근거 |
|---|---|---|---|
| 게이트웨이 본체 | **LiteLLM proxy** | MIT | 훅 4종이 필요한 심(seam)과 정확히 일치. 프록싱은 커머디티이므로 재구현하지 않는다 |
| PII 프레임워크 | **Presidio** | MIT | Recognizer 추상화. 단 기본이 영어 전용이라 **한국어 recognizer는 직접 작성** — 이것이 축 A의 실체 |

| 업스트림 생성 LLM | **Gemini API** (`gemini-3.6-flash`) + **Gemma 4 E4B 로컬** | **Apache 2.0** (Gemma 4) | 브리프의 "gemma4" 요건. Gemma 4는 2026-03 출시로 **Gemmaverse 최초 Apache 2.0** — Gemma 3의 ToU 전파 의무·해지 조항이 사라진다 |

기각한 후보와 사유는 [MARKET_RESEARCH §6.2](MARKET_RESEARCH.md#62-검토-후-기각)에 있다. 요지: Llama Guard·Prompt Guard 계열은 한국어 공식 미지원 + Llama 라이선스, ShieldGemma는 영어 중심이며 Gemma 4 기반 후속이 없다, Cloudflare AI Gateway는 프롬프트가 외부로 나가 제품 논리와 모순된다.

**라이선스 판정**: 채택 스택 전체가 MIT 또는 Apache 2.0으로, 상용 배포까지 제약이 없다. 브리프의 "on-device 모델 라이선스 확인" 요구를 이 표가 충족한다.

### 4.2 통합 전략

가드 캐스케이드와 레이턴시 예산의 상세는 [ARCHITECTURE §4](ARCHITECTURE.md#4-가드-캐스케이드와-레이턴시-예산)에 있다. 원칙만 옮기면:

- **저비용 결정적 검사를 앞에** — 정규식 + 체크섬 + 볼트가 L0에서 10ms 안에 끝난다
- **모델 추론은 예산 안에서만 동기로** — Kanana 2.1b와 privacy-filter 50M만 동기 경로에 두고, 8B 모델은 전부 비동기 감사 라벨링으로 뺀다
- **탐지는 전부 로컬** — PII를 탐지하려고 PII를 외부로 보내는 것은 자기모순이다([ARCHITECTURE §9](ARCHITECTURE.md#9-온디바이스--api-분리-원칙))

### 4.3 파인튜닝 — 두 과제

기본 방침은 학습하지 않는 것이다. 한국어 유해성에서 Kanana Safeguard(F1 0.946)를 솔로가 이길 수 없고, 구 프로젝트의 klue/roberta 결과(span F1 0.9845)는 row-level random split의 누수 가능 상한이라 헤드라인이 될 수 없었다.

다만 **로컬 실행이라는 제약에서 필연적으로 따라오는 두 개**는 한다. 학습을 위한 학습이 아니라 설계가 요구하는 학습이다.

| # | 과제 | 왜 필요한가 |
|---|---|---|
| **R1** | 한국 PII NER 파인튜닝 | 어떤 공개 모델도 한국 고유 식별자 태그를 갖고 있지 않다. privacy-filter 9종에도, Google SDP 6종에도 법인등록번호가 없다 |
| **R2** | 인젝션 분류기 distillation | **2B 교사(kanana)를 노트북 CPU 인라인에 둘 수 없다.** 메모리 4.2GB에 레이턴시 예산도 못 맞춘다. 0.1B로 줄이지 않으면 로컬 실행 자체가 성립하지 않는다 |

학습 데이터·방법·평가 설계의 상세는 [MODEL_AND_TRAINING §4~6](MODEL_AND_TRAINING.md#4-학습-및-테스트-데이터)에 있다. 판단 게이트는 [ROADMAP W3](ROADMAP.md#w3--가드-캐스케이드--흐름-판정--데모-에이전트).

## 5. 성능 평가 및 검증 계획

### 5.1 평가 원칙 5조

구 프로젝트의 실패를 직접 겨냥한 규칙이다. [ROADMAP](ROADMAP.md#평가-원칙-5조)에도 같은 내용을 둔다.

1. **평가 설계 고정** — 지표·n·통계 방법을 W4 착수 전 별도 커밋으로 고정한다. "사전등록"이라는 용어는 쓰지 않는다. 구 프로젝트가 PREREGISTRATION.md를 결과와 같은 커밋에 넣고 조건(P5) 위반 후에도 결론을 유지한 전례가 있어, 그 용어가 주는 신뢰를 빌리지 않는다.
2. **재현율 옆에 항상 FPR** — 모든 재현율·차단율 헤드라인은 같은 표에 오탐률을 동반한다. 예외 없다.
3. **동어반복 금지** — 헤드라인 지표는 "이 시스템이 질 수 있는가" 테스트를 통과해야 한다. 구성상 100%가 나오는 지표(예: allowlist 밖 발송을 성공으로 정의한 뒤 allowlist를 켜는 것)는 헤드라인이 될 수 없다. 최소 한 개의 베이스라인이 어딘가에서 이기거나 비기는 표를 목표로 한다.
4. **n은 군집 단위로** — 시나리오 × 스타일의 곱을 행 수로 세지 않는다. 통계는 군집 인지 방법(cluster McNemar)만 사용하고, 행 단위 p값을 보고할 경우 exploratory로 명시한다.
5. **레이턴시는 하드웨어 선언 후** — CPU/GPU 사양, 배치 크기, 모델 로딩 방식을 명시하지 않은 지연 수치는 보고하지 않는다.

### 5.2 베이스라인

비교 대상이 없으면 숫자에 의미가 없다. 다음을 같은 코퍼스에서 돌린다.

| 베이스라인 | 무엇을 보여주는가 |
|---|---|
| **정규식 단독** (체크섬·문맥 없음) | 체크섬과 문맥 단어가 FPR을 얼마나 줄이는가 (M3) |
| **vanilla Presidio** (기본 영어 설정) | 한국어 recognizer 작성의 실제 효과 |
| **privacy-filter-korean 단독** | 정규식 스위트와 NER의 보완 관계 — 어느 쪽이 어떤 엔티티에서 이기는가 |
| **LLM Guard 스캐너 구성 이식** | 아카이브된 레퍼런스 대비 위치 (코드가 아니라 설정 개념만 이식) |

### 5.3 통계 방법

구 프로젝트의 `eval/stats.py`(Wilson 신뢰구간, McNemar exact, cluster McNemar)를 재사용한다. 원칙 4에 따라 군집 단위 검정을 주 결과로 삼고, 다중 비교가 발생하면 보정 후 유의성을 판단하며 보정 전후를 모두 보고한다.

### 5.4 오류 분석

지표만 보고하지 않는다. 오탐·미탐 사례를 유형별로 분류한 실패 taxonomy를 만들고, 각 유형에 대해 구조적 원인(정규식의 한계인지, 모델의 한국어 커버리지인지, 정책 설계인지)을 기록한다.

|---|---|---|---|
| R1 | KDPII 라이선스 확인 실패 | 낮음 | **합성 코퍼스를 기본으로 하고 KDPII는 보강으로 둔다.** 재검토에서 이것을 W1 블로커로 규정한 것이 과했다고 판단했다 — 대안이 합성이면 애초에 블로커가 아니고, PII 평가는 오히려 합성이 유리한 면이 있다(유효/무효 체크섬/형식유사 비-PII를 통제된 비율로 생성 가능) |
| R2 | **조사 처리를 위한 형태소 분석기 의존** — kiwipiepy는 LGPL | 라이선스 조합이 깨질 수 있음 | W1에 대안 3개 비교: (a) LGPL 동적 링크 허용 범위 검토, (b) 조사 사전 기반 규칙(형태소 분석기 없이), (c) 마스킹 토큰 뒤 조사를 원문 그대로 보존하는 우회. 결정을 문서화 |
| R3 | **Kanana 8B 계열의 GPU 요구** | 비동기 라벨러 구동 불가 | 애초에 비동기 경로에만 배치했으므로 동기 성능에 영향 없음. GPU 부재 시 CPU 배치 처리 또는 해당 라벨러 생략 가능하도록 설계 |
| R4 | **자작 벤치마크의 자기편향** — 공격 제작자와 방어 제작자가 같은 사람 | 결과 신뢰도 저하 | 한계 절에 명시 + 외부 셋(`korean-guardrail-dataset` 인젝션 5K)을 held-out으로 사용. 구 프로젝트가 MAPS 400건을 자체 60건으로 조용히 대체한 전례를 반복하지 않는다 |
| R5 | **LiteLLM 훅 API 버전 변동** | 구현 재작업 | 버전을 lock으로 고정하고, 훅 어댑터를 얇게 유지해 교체 비용을 낮춘다 |
| R6 | **Presidio 커뮤니티 이관 후 PR 수용 불확실** | 업스트림 기여 서사 약화 | 기여는 부가 목표로 두고, 독립 패키지(`presidio-recognizers-ko` 형태)로도 쓸 수 있게 설계 |
| R7 | **MCP 스펙 유동성** | tool-call 층 설계 변경 | ⚠️ **재검토에서 대처를 바꿨다.** 종전에는 MCP 프록시를 6주차 스트레치로 뒀는데, 그러면 축 C가 5주 종료 시점에 강제력 없는 상태로 남는다. **MCP 게이트웨이를 본선(W2~W3)으로 올린다.** 스펙 유동성은 인터셉트 대상을 `initialize`/`tools/list`/`tools/call` 셋으로 좁히고 나머지는 패스스루해 흡수한다 |
| R8 | **Gemini API 비용·쿼터** | 데모·평가 중단 | 구 프로젝트에서 실제로 발생했다(60건 중 59건이 429로 실패). 평가는 로컬 가드 모델 중심으로 설계해 업스트림 호출 의존을 최소화하고, Gemma 4 로컬 경로를 폴백으로 둔다. free tier는 데이터가 학습에 쓰이므로 실제 프롬프트에 쓰지 않는다 |
| R9 | **레이턴시 예산 초과** | 제품 논리 훼손 | 동기 경로에는 소형 모델만. 초과 시 (a) 병렬 fan-out, (b) 캐스케이드 조기 종료, (c) 해당 검사를 비동기로 이동 순으로 대응하고 무엇을 뺐는지 기록 |
| R11 | **두 심의 세션 상태 동기화** | 토큰 오복원 — 다른 사람의 PII가 복원될 수 있다 | 재검토에서 발견한 결함 2. 볼트 스코프를 `task`로 올리고 두 심이 세션 ID를 공유한다. TTL 900초·매핑 상한 500으로 팽창을 막고, 테넌트 격리를 세션 ID에 바인딩한다 ([AGENT_SYSTEM §3](AGENT_SYSTEM.md#3-세션-상태--두-심을-잇는-것)) |
| R12 | **rehydrate 대칭 가정** | 마스킹이 무의미해진다 | 재검토에서 발견한 결함 4. internal 도구에 실제 PII를 넘기면 반환값에도 실제 PII가 있다. **복원은 단방향, 반환값은 항상 재마스킹** ([AGENT_SYSTEM §5.3](AGENT_SYSTEM.md#53-rehydrate는-단방향이다-결함-4의-교정)) |
| R10 | **5주 범위 초과** | 미완성 산출물 | 주차별 검증 기준을 외부에서 확인 가능한 형태로 정의하고, 미달 시 스트레치 항목부터 잘라낸다. 잘라낸 것은 로드맵에 남긴다 |
